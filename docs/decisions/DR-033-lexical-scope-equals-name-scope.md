# DR-033: lexical スコープ = name が作るスコープ。command に限らない

## 決定

DR-025 で保留した「lexical スコープ」は、結果スコープと同一単位である。**解決後の結果キー (`export_key` 軸) を占有するノードがスコープを作る** (結果スコープ = lexical スコープ、同一)。command は children を持つから特別なのではなく、結果キー軸を占有する多くのノードの一つにすぎない。

> **更新 (TRG-Q4=a、kawaz 裁定 2026-08-15): 判定基準を「name を持つ」から「結果キー軸を占有する」へ訂正 (DR-025 の同名更新注記と対)。** 本 DR の主張「lexical スコープと結果スコープは同一単位」はそのまま生きており、変わったのはその単位を決める条件である。したがって `export_key: null` のノードは**両方のスコープを作らない** — 結果が透けるなら名前も透ける。透けるのは名前解決の面だけで、パース経路 (トリガ照合・入場・背骨) は不変。

## ref/link の name 解決

ref/link の参照識別子の解決は、現在スコープから外側へ**結果キー軸を占有するノード**のスコープを順に辿る (レキシカルスコープチェーン)。command に限らず内側のノードもスコープ単位。見つからなければ最後に definitions (DR-032)。

## 例 (kawaz)

color.rgb の中で r/g/b を DRY に定義: rgb の seq 内で r を定義し、g/b は ref:"r" で継承。rgb スコープ内で r が見えるので g/b が r を ref できる。command をまたがず内側スコープで lexical 解決が起きる。
