# DR-138: union 値の枝並行構築と確定相淘汰 — 完成判定・後勝ち・tie、DR-127 の union 動的規定を supersede

> 由来: kawaz 裁定 (2026-08-14〜16、ccmsg mid=9-10 / UC-Q1〜Q3 / mid=32-34)。正本ノートは
> `docs/research/2026-08-16-union-culling-settlement.md` (導出と発明の峻別、および
> `docs/research/2026-08-13-value-capsule-design.md` §5.6/§6.2 のレビュー 3 系統の指摘の裁き)。
> **DR-127 §2.2 の union 行の実行時規定と §4 の時系列適用の union セルへの適用を supersede
> する** (§9 の逐条表が範囲の正本)。DR-029 / DR-031 / DR-037 / DR-038 / DR-045 / DR-047 /
> DR-120 / DR-126 / DR-128 / DR-130 は supersede しない — 本 DR の設計はこれらが無傷で
> 生き残るように位相を切ってある。前提 DR は DR-126 (union / record) と DR-137 (tuple)。

## 決定

### 0. 用語

| 語 | 意味 |
|---|---|
| **書き込み** | セルへの効果 (DR-045 の効果記述子 1 件)。丸ごと set (parser 産出含む) と path 部分書き (DR-127 §2) の両方 |
| **枝** | union value_type (DR-126 §1) の 1 variant に対応する、セル内部の候補構築状態 |
| **着地** | 書き込みがある枝の構造に適合して受理されること (§2) |
| **座の充足** | 枝の型構造が要求する座が埋まっていること (tuple の位置 / record の presence)。要素属性 `required` (DR-047 の値述語) とは別位相 (§4) |
| **確定相** | 経路の消費が終わり、セル値を確定させる相 (DR-047 §4 の「最終状態」を作る側) |

### 1. 枝の「完成」は型レベルの構造述語

枝が完成しているとは、**候補値がその枝の value_type の完成値として適合すること**である:

| 枝の value_type | 完成条件 |
|---|---|
| **tuple** (DR-137) | 全位置が non-null — 位置は全て構造上必須 (全座充足が値の意味、DR-137 §2)。`[0, 255, null]` は未完成 |
| **record** (DR-126) | closed キー適合のみ — フィールドは presence-optional (DR-126 §3) なので、着地が 1 件以上あれば部分値 (`{until: X}` 相当) でも完成 |
| **primitive** (`string` / `number` / `bool` / `null` — DR-126 §1 の value_type 列挙の primitive) | 型適合の値の着地が 1 件以上ある |
| `array` / `map` / `value` | 型適合の丸ごと set の着地が 1 件以上ある (部分構築は生じない — array は vivify 不可、map / value は器の形が定義時に言えない。DR-127 §2.2/§3 不変) |

完成判定は**確定相の内部工程**であり、node `required` は**できた最終セル値への述語**
(DR-047) である — 2 層を混ぜない (kawaz mid=32-34)。

### 2. 淘汰規則 — 並行着地 → 未完成淘汰 → 最終着地の後勝ち

union 宣言セルに **1 件以上の書き込み (CLI / link 効果) があるとき**、以下で値を確定する:

1. **並行着地**: 各書き込みは、その形が適合する**全ての枝**へ並行に着地する — 丸ごと set は
   型適合する全枝へ、path 部分書きはそのパスを構造に含む枝へ (含まない枝には着地しない
   だけで、Reject も Error も発生しない)。同一枝内の複数の着地は従来どおり出現順の操作列
   として fold する (DR-029 の時系列適用 — 枝内では不変)
2. **淘汰**: 確定相で、未完成 (§1) の枝を淘汰する
3. **後勝ち**: 生存枝のうち「その枝への最終着地」が時系列で最も新しい枝の値がセル値になる。
   時系列は効果列の出現順 (DR-029) であり、新しい座標軸は導入しない

規範例 (kawaz 承認済みの color 3 ケース。`--r`/`--g`/`--b` は `color[0/1/2]` へ link、
`--color` は string を丸ごと、type の out は `[{"tuple": ["int","int","int"]}, "string"]`):

| 入力 | tuple 枝 | string 枝 | 結果 |
|---|---|---|---|
| `--r 0 --g 255` | `[0, 255, null]` (未完成) | 着地なし | 生存ゼロ → 経路不成立 (§4) |
| `--r 0 --g 255 --color red` | `[0, 255, null]` (未完成、淘汰) | `"red"` (完成) | `"red"` — `--r`/`--g` は敗北枝の着地として消える。**エラーではない** |
| `--r 0 --g 255 --color red --b 0` | `[0, 255, 0]` (完成、最終着地 pos) | `"red"` | 後勝ちで `[0, 255, 0]` |

後勝ちの基準は**最終着地**であって完成順ではない — `--r 0 --b 0 --g 255 --color red` は
tuple が先に完成していても、最後に触られた枝は string なので `"red"` が勝つ
(最後に触った枝がユーザの意図)。

書き込みゼロの union セルは淘汰規則の対象外である — 全枝が「未着手」であって「未完成」
ではない。通常のラダー (§3) に従い、どの席も無ければ DR-130 §1 の `null` が座る
(成功 result、キーは立つ)。node `required` があれば DR-047 の不充足 (`required_violated`)
であって §4 の生存ゼロエラーではない。

### 3. 値源ラダーはセル単位で 1 回 — 枝ごとに回さない

DR-031 のラダー (CLI/link > env > config > default) は**セル単位**の規則のまま変えない
(DR-031 追記「1 実体の値 cell 内で値源を選ぶ規則」/ DR-120 §1「1 露出キー 1 値セル」—
枝はセルの内部表現であってセルではない)。

- セルへの CLI/link 書き込みが 1 件以上あれば下位席は発火しない — **淘汰の結果が生存ゼロ
  でも下位席は救済しない** (CLI が最優先である以上、CLI の供給がある限り下位は上書き
  できない — DR-031「明示的に与えられたものほど優先」の帰結)
- 下位席 (env / config / default) の供給は**完全値 1 発**として通常の値パイプラインで
  parse され (DR-049 / DR-050)、枝並行構築は起きない — 産出がどの variant に適合するかと
  いう通常の型判定だけが残る — この型判定には §1 の完成判定が含まれ、完成値でない tuple 値の
  供給は型不適合である (DR-137 §2。`incomplete_value` = CLI/link の組み上げ失敗とは別位相)。部分書きの機構 (link パス) は CLI/link 層の住人であり、
  下位席に部分書きの席は無い (config_key は文法借用のみ、DR-127 波及節) ため、
  「未完成枝」を作れるのは構造的に CLI/link だけである — 「下位席が枝を完成させる」状況は
  発生しない

### 4. 生存ゼロは完全経路の不成立 — kind `parse` / reason `incomplete_value`

書き込みが 1 件以上あって生存枝がゼロの読みは、**完全経路と数えない** (Error 保持の
経路不成立)。DR-047 §2 の遅延述語と同じ席 — 「経路の成立条件の精密化で 1 本に絞る」の
適用であり、**DR-047 §2「1 本確定後の事後検証層は持たない」は supersede せず生きる**。
他の読みが完全経路を成立させればそれが選ばれ、保持された Error は捨てられる (DR-037)。
全読みで不成立なら保持された Error を表示する。

- **kind / reason**: 新 kind は興さず、既存 3 kind 体系 (CONFORMANCE §2) の
  **`parse`** に **reason `incomplete_value`** を追加する (エンジン構造発生源、
  REFERENCE §7.3)。「供給はあったが値が組み上がらなかった」は型照合・経路構築の失敗の
  一族である
- **単相セルにも同じ reason が効く**: union でない tuple 宣言セルが確定相で null 座を
  残した場合も `incomplete_value` である (淘汰すべき他枝が無いので直ちに経路不成立)。
  union なら淘汰、単相ならエラー — **同じ完成判定 (§1) の 2 つの現れ**であり、
  reason を分けない。record 単相は presence-optional のため未完成状態が無く、
  この reason を発しない (部分値の締めは `required` / filter の関心 — DR-126 §3 の線)
- **args_pos 帰属**: 当該セルに着地した書き込みのうち **argv 位置最深**のものの operand
  位置 (DR-053 の primary = argv 位置最深と同原理 — 最後に触った操作が意図の座標)。
  argv 位置を持たない書き込みしか無い場合は消費位置 (DR-127 §4.2 の既存規則)。
  element は当該セルの参照識別子
- **文言ガイド (kawaz 指示)**: message はレンダラの関心 (DR-053) だが、
  **`union` / `branch` / 「枝」等の内部実装語をエンドユーザ向け文言に出さない** —
  ユーザが書いたのは `--r 0 --g 255` であって union ではない。「値が組み上がらなかった /
  何が足りないか」を利用者の語彙 (要素名・受理形) で語る (interface-wording の一般則の
  本件への確認)

### 5. tie — 観測値が同値なら成功、異値なら ambiguous

複数の生存枝の最終着地が**同一の書き込み** (丸ごと set が複数枝に同時適合する等) で
時系列比較が tie になる場合:

- tie した枝の**確定値を観測面 (結果射影後の形 — record は DR-130 §4.1 の null 補形適用後)
  で比較**し、**同値なら成功** (その値で確定)、**異値なら ambiguous** (interpretations に
  各枝の**結果ビュー (null 補形適用後)** を列挙する — DR-130 §4.2 の sparse 規範への
  carve-out (同 §4.2 追補、DR-053)。形の違いこそが曖昧の内容なので補形を省けない)
- 根拠は DR-031 EXP-Q1 の直接の同型 — 同値 default は「観測可能な競合が無い」ため
  success、異 default は ambiguous。宣言順等の順位規則で解決しないのも同じ線
  (DR-038 / DR-042 の順序非依存)
- 帰結: フィールド集合の異なる record variant が共有フィールドを持つ union で、共有
  フィールドへの 1 書き込みだけが supply されると、両枝が完成・tie し、射影後の値
  (`{a: 1}` vs `{a: 1, b: null}`) が異なるため **ambiguous になる** — どちらの形を
  意図したか本当に決まらないケースの正しい検出である
- 同値 tie は、構造的型付け (variant の同一性を値に保存しない、DR-127 §2.2) と全列挙射影
  (DR-130) の下では variant の観測形が一致する場合に限られ、現行の型ビークルでは
  ほぼ構成できない — 規則は総和として置くが、pin は異値側で行う (§波及)

なお枝間の時系列比較が「比較不能」になる軸 (CLI 由来 vs 非 CLI 由来) は存在しない —
枝並行構築は CLI/link 効果列の内部に閉じる (§3) ため、比較対象は常に同一効果列上にある。

### 6. 書き込み単位の失敗と淘汰は別位相

淘汰に吸われるのは**座の充足の欠落** (後続の書き込みで治りうる状態) だけである。
書き込み自体の失敗は従来どおり書き込み時 (parse 時) に裁く:

| 失敗 | 位相 | 扱い |
|---|---|---|
| (a) operand の型不正 (`--r abc`) | 書き込み時 | operand は着地座の type のパーサを通る (DR-127 §3.2 / DR-137 §4)。失敗は当該発生源の Reject / Error (DR-037) で読みの成立に効く。args_pos = 原因トークン。**淘汰で沈黙しない** — union に入れた途端 `--r abc` が黙って消える非対称を作らない |
| (b) パスが枝の構造に無い | 静的 + 適用時 | 静的: パスを含む variant が 0 なら definition-error、含有 variant 間の型不一致も definition-error (DR-127 §2.2 の静的規定 — 不変)。適用時: 含まない枝には着地しないだけ (§2-1) |
| (c) filter Reject / (d) filter Error | 書き込み時 | 従来どおり (DR-037) |
| (e) 座の充足の欠落 | **確定相** | 枝淘汰 (§1)。エラーではない — 生存枝があれば黙って負ける |
| (f) node `required` | 遅延述語 | §4 冒頭の位相列のとおり、最終セル値への値述語 (DR-047 不変) |

### 7. 観測面 — effects はセル単位 1 entry、sources は勝ち枝

- **effects**: 実際に発生した操作を一度だけ時系列記録する (DR-045 不変)。枝への並行着地は
  内部表現であって効果ではない — 1 書き込みが 3 枝に着地しても effects は 1 entry。
  **敗北枝にしか着地しなかった書き込みも effects に残る** (「効果は観測記録であって
  最終状態ではない」— `fixtures/link-parse/value-residual-timeline.json` が単相セルで
  pin 済みの規則の適用)。`path` は宣言パスの segment 列のまま (DR-127 §6) — どの枝に
  着地したかは観測アドレスではない
- **sources**: 勝ち枝の値の座だけがタグを持つ (sources は result の shadow — DR-122 §2
  「キー集合は result の射影」)。敗北枝の着地はタグを残さない。勝ち枝内の座タグは
  既存規則 (DR-127 §6 の座単位 re-tag、tuple は位置対応の配列 — DR-137 §2) のまま
- effects が枝表現に依存しないため、**DR-038 の経路同一性 (効果列基準) は不変** —
  枝候補集合の導入は経路の数え方を変えない

### 8. 消費の or との分離 — 別機構として立てる

値のセル union と、消費構造の or (DR-018 / DR-067 の排他枝) は別機構である。線引きは
**「トークンの食い方を分岐させるものは消費の or、食い方が同じで値の型だけが分岐する
ものはセル union」**:

| | 消費の or | セル union (本 DR) |
|---|---|---|
| 分岐の対象 | argv の消費構造 (何トークン食うか、どの入口か) | 1 セルの値の型 (variant) |
| 判定時点 | parse 時 — 経路探索が枝を選ぶ (DR-038 完全経路) | 確定相 — 淘汰 + 後勝ち |
| 敗者の観測 | 未選択枝の named 座は result に `null` (DR-130 §2 / DR-127 §4.1b) | 敗北枝は観測に存在しない (セルは 1 つ、値が 1 つ) |
| 曖昧の裁き | 完全経路 2 本以上 = ambiguous (DR-038) | tie の異値 = ambiguous (§5) |

`input_structure` の or (DR-128) は消費の or 側である — type が持つ入口の文法の分岐は
sub-parse のトークン消費を分けるので parse 時に選ばれ、その**産出がどの variant に
適合するか**が確定相の関心。同じ type に両方が同居しても位相は混ざらない。

また、枝並行構築は**出力側の候補集合**であり、DR-127 §5 が禁じた**入力側の候補バッファ**
(「入力が揃うまでパースを保留する」) ではない — 各書き込みの parse は着地時に即時完了
しており (§6 (a))、保留される入力は存在しない。§5 の禁則は無傷で生きる。

### 9. DR-127 の supersede 範囲 — 逐条表

supersede は「union 宣言セルの動的挙動」に限定される。**単相セルの全規定は無傷**であり、
既存 fixture への影響はゼロ (union value_type の動的枝 Reject を pin した fixture は 0 件、
`fixtures/link-parse/` の現行 11 本は全て単相セル — 起草時 grep 実測)。

| DR-127 の節 | 判定 | 内容 |
|---|---|---|
| §1 / §2.1 / §2.3 | 生存 | 変更なし |
| §2.2 遷移表の record / array / map・value / primitive 行 | 生存 | 変更なし (tuple 行の追加は DR-137 §4) |
| §2.2 union 行の**実行時規定** (「実行時の現在値の構造で判定 — 合わなければ枝 Reject」) | **supersede** | 置換先は §2-1 / §6 (b) — 並行着地・非着地であり枝 Reject は発生しない。枝の生死は確定相の淘汰が決める |
| §2.2 union 行の**静的規定** (variant 0 / 型不一致 = definition-error) | 生存 | 変更なし |
| §3 (vivify) | ほぼ生存 | union の「含有 variant の器」は**適合する全 variant の器を並行 vivify** (1 個を選ばない) へ読み替え。他は不変 |
| §3.1 / §3.2 | 生存 | §6 (a) がむしろ依存する |
| §4 冒頭 + 時系列表 | **縮小生存** | 「時系列適用が全ケースを決める」の射程は**単相セル、および union セルの枝内**に限定される。union セルの枝間は §2 の淘汰 + 後勝ちが決める (表 2 行目相当の帰結が変わるのは union 宣言時のみ) |
| §4.1 / §4.1b | 生存 | 変更なし (§4.1b は消費の or の規定 — §8 の左列) |
| §4.2 | 縮小生存 | 枝ローカル fold と全枝落ち ParseError 合成の要求は生存 (map / value の実行時解決失敗が残る)。union variant 不適合が fold の失敗条件から抜ける。args_pos 規則は §4 の生存ゼロ帰属が流用する |
| §5 (入力側部分注入禁止) | 生存 | §8 末尾のとおり両立 (供述の区別を §5 側に注記) |
| §6 (sources / effects) | 生存 + 追補 | §7 の 3 規定を追補 |
| §7 (DR-029 分界追補) | 生存 | 変更なし |

DR-029「操作の時系列適用」も生存する — 時系列はセル効果列の順序として不変で、本 DR は
その適用先が union セルでは枝候補集合になるという消費側の変化である (counter / link の
典型例 = 単相 number セルは無傷)。

## 根拠

### 淘汰の遅延は既存原理の適用位相違い + 候補集合という新規部分

遅延述語 (DR-047)・held errors (path-search)・child default preemption と同型の
「完走後に裁く」パターンだが、既存が reading (経路) の淘汰であるのに対し、本件は
**1 つの値セル内部に枝別構築状態の候補集合を持つ**点が新しい。新規部分を確定相に閉じ込め、
書き込み時の裁き (DR-037) とラダー (DR-031) と経路計数 (DR-038/047) を全て既存のまま
残す位相の切り方が、supersede 範囲を §9 の 2 箇所に絞る。

### 生存ゼロを経路フィルタに置くから DR-047 が生きる

生存ゼロを確定相の即エラーにすると DR-047 §2 (事後検証層を持たない) の supersede が要り、
union セルを含む読みの失敗が他の読みの成功を巻き込んで DR-037 (他ルートが通るなら
エラーは捨てる) に反する。経路フィルタ側に置けばどちらも既存のまま成立する。

### tie を EXP-Q1 の線で裁く

観測可能な差が無い競合をエラーにしない (同値 default = success) と、順位規則で黙って
選ばない (異 default = ambiguous) の 2 面は DR-031 EXP-Q1 で既に裁かれており、
「1 セルの値を複数の主体が主張する」構図は同一である。

## 採用しなかった案

### color を record 化して DR-127 §3/§4 (vivify + 時系列) の枠内で書く

opus C2 の提案。枝並行構築なしで書けるが、`--color red --b 0` で parser 産出 `"red"` に
部分書きが乗る (DR-127 §4 表 2 行目) という帰結になり、kawaz 承認済みの 3 ケース表
(後勝ちで tuple 復活) と両立しない。裁定 (mid=9-10) で棄却済み。

### 枝ごとの独立ラダー

未完成枝を default が補完できる表現力は増えるが、DR-031 / DR-120 のセル単位を破り、
「default が生存して既存意味論が変わる」。確定裁定はこの表現力を要求していない。

### 型不正の書き込みも淘汰に吸わせる

診断の喪失 (args_pos が取れない — DR-127 §5 が入力バッファを棄却したのと同じ理由) と、
単相セルとの非対称 (union に入れた途端 `--r abc` が沈黙する)。

### tie の無条件 ambiguous

観測可能な差が無い場合までエラーにするのは DR-031 EXP-Q1 の裁きと非対称で、実害の無い
場面でユーザにエラーを課す。

### 生存ゼロの新 kind

「供給はあったが組み上がらない」は型照合・経路構築の失敗の一族であり、既存 3 kind
体系の `parse` に reason で乗る。kind の増設は conformance 比較面の語彙を実装横断で
増やすコストに見合う識別価値を持たない。
