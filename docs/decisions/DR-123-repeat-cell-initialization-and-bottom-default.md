# DR-123: 反復セルの初期化位相と暗黙 bottom default — `[]` は最初から居るのではなく最下段が供給する

> **更新 (DR-125、2026-07-29): §2 の値源席の列挙から `inherit` が抜けた。** 空席の反復セルに対して
> 回るラダーは DESIGN §11.4 の 4 段 (env / config / default) で、暗黙 bottom default が `[]` を
> 供給する規則そのものは不変。

> 由来: child 位置の repeat fixture 整備 (2026-07-28) で「repeat 宣言子に `default:` を書いたとき 0 発火の結果は何か」の導出が割れ、REPDEF-Q1 として起票した論点。`[]` が常にセルに居るという読みを採ると `default:` が到達不能な影になり、unset のラダー開放 (DR-045 §2) も意味を失う。kawaz 裁定 (2026-07-28): 「repeat や multiple のように値セルが配列になる場合、初めから `[]` があると見るのは間違い。初めてトリガされた瞬間に `[]` 初期化されると見るべき。そうすれば default も既存どおり自然に充填可能だし、no:unset みたいなのの動作も整合が取れる。また『default が無いなら `[]` が充填される』は、ラダーの最後の、default が無い時の暗黙 default が `[]` に当たる、という配置換えが正しい」。

## 決定

### 1. 反復セルの `[]` は初期値ではなく初回発火の産物

repeat / multiple / `optional: true` 糖衣 (以下まとめて**反復セル**) の値セルは、**発火するまで値を持たない** (空席)。初めてトリガされた瞬間に `[]` で初期化され、そこへ accumulator が発火値を畳む。

`value:` の const 初期化 (DESIGN §5.2 — セル初期化位相に属し、値セルに最初からいる) とは位相が違う: const は宣言によって最初から座っている値、反復セルの `[]` は**発火という出来事が作る**器である。「反復セルには最初から `[]` が座っている」という読みは採らない。

この区別は観測可能である。`empty` op で明示的に空にしたセル (committed=true、値 `[]`) と、一度も発火していないセル (空席) は、同じ `[]` を結果に出しうるが位相が異なる — 前者は発火済みでラダーを回さず、後者は空席として §2 のラダー解決へ進む。両者の区別は `effects` の op が担う (DR-122 §2.1 が `sources` から落とした committed 軸の情報は、ここで意味を持つ)。

### 2. 未発火の反復セルは値源ラダーが埋める

発火しなかった反復セルは空席なので、**通常どおり値源ラダー (DR-031、DESIGN §11.4 の 5 段) が回る**。env / config / inherit / default のいずれかが宣言されていればその席が値を供給し、`sources` はその席を指す。

これは DR-083 §4 (multiple 要素のラダー供給時: 未発火・uncommitted なら sources = default_source) を反復セル全域へ広げたものであり、multiple と repeat で規則を分けない。宣言 default 不在時の暗黙 default `[]` を宣言 default が置き換える規則は、repeat を含む反復セル一般に適用する。

### 3. `[]` はラダー最下段の暗黙 default (配置換え)

「0 発火なら `[]`」は独立した結果整形規則ではなく、**ラダー最下段の位置づけを持つ**: 反復セルの default 席は、`default:` が宣言されていなければ暗黙に `[]` を供給する。宣言があればその値が席を占める (DR-083 §1)。

この配置により、反復セルは default 席が常に埋まっている (宣言 default か暗黙 `[]` か) ため、DR-130 §1 の成功 result で `null` にならない。型導出も native default ありの分岐により `T` となる。

> **適用範囲の明確化 (2026-08-16): 本項は「実現した経路上のセル」の規則である。** `[]` は
> **ラダー最下段の default 席が供給する値**なので、ラダーが走らないセルには供給されない。
> 具体的には **未選択の `or` 枝の内側にある反復セルは `[]` ではなく `null`** になる —
> DR-130 §4 の named 枝の or 席が「**未選択枝の default は充填せず、枝の default はその枝が
> 選択された場合だけ生きる**」と規定しており、暗黙 `[]` もその「枝の default」だからである。
> 上の「`null` にならない」が参照しているのも DR-130 **§1** (実現したスコープの全キー列挙) で
> あって §4 ではない。
>
> したがって二段構えになる: **枝が実現していない → `null` (DR-130 §4 / §2 が優先)**、
> **実現したスコープで 0 発火 → `[]` (本項)**。pin: 前者は
> `fixtures/or-parse/child-repeat-branch.json`、後者は
> `fixtures/or-parse/option-structural-or-outer-repeat.json`。

`unset` fn が返す null を反復セルへ set すると committed=false でラダーを開放し、下位席があればその値が供給され、無ければ最下段の暗黙 default `[]` に落ちる (DR-131 §2、`fixtures/multiple-parse/unset-env-fallback.json`)。

なお最下段の暗黙 default が供給する `[]` には値の座が無いため、`sources` にはタグが載らず `[]` のままである (DR-122 §2) — DESIGN §11.4 の「未発火要素の sources は `default`」は値の座を持つセル (flag の `false` 等) の規則であり、空コレクションはその適用対象ではない。

### 4. `min` は消費読みの内部規則、`default:` は消費するか否かの規則 (β=a)

`repeat: {min: 1}` を持つ要素に `default:` を宣言した場合、**0 発火のまま完全経路になり、default がセル全体を埋める**。

両者は層が違う。`min` は閉包が**消費読みとして成立するときの**内部制約であり、必須段の unroll として枝生成に効く (DR-043) — 消費読みを採るなら 1 回以上反復しなければならない。一方 `default:` は DR-088 §1 の「宣言された値源 = デフォルトの存在」により、**その要素の座を消費で埋めなくても完全経路に含めてよい**という充足判定を与える。DESIGN §5.2 が「`default:` を持つ子は消費 0 の literal にならない — 通常どおり消費を試みる子のままで、`default:` が変えるのはトークンを得られなかった消費点を空席のまま完全経路に含めてよいという充足判定である」と述べる規則が、閉包を持つ要素にもそのまま及ぶ。

したがって `repeat: {min: 1}` + `default:` は「1 回以上消費する、さもなくば default」を意味し、`min` の値は消費読みが成立する場合にのみ効く。

枝の生成順は DESIGN §5.2 の逐次先食い規則に従うので、消費読みが完全経路へ届く限り空席枝は立たない (default が消費読みを押しのけることはない)。トークン不足・型 Reject・downstream 不達で消費読みが立たないときにだけ空席が確定し、ラダーが default を充填する。

セル全体を埋める以上、反復セルの宣言 default は分割済み pieces として与える (DR-083 §2)。scalar 要素への配列 default が definition-error である規則 (DR-083 §5) の裏返しとして、反復セルの default は配列で書く。

## 採用しなかった案

### `[]` は常にセルに居るので `default:` は到達不能な影 (影説)

REPDEF-Q1 の起票時に「DR-044 / DR-051 との整合が最も良い」として推された読み。`value:` の const がラダー席を影にするのと同型 (DESIGN §5.2 末尾) と見て、反復セルの `default:` は書けるが常に無意味 (静的検出は lint の領分) とする。

不採用の理由は 2 つ。第一に、DR-083 §1 が multiple の宣言 default を「暗黙 default を置き換えるもの」として既に尊重しており、repeat だけ影にすると反復セル内で規則が割れる。第二に、`unset` のラダー開放 (DR-045 §2) が意味を失う — セルに常に `[]` が居るなら「開放して下位席へ落ちる」余地が構造的に無く、`fixtures/multiple-parse/unset-env-fallback.json` が pin 済みの env フォールバックを説明できない。影説は「`[]` を初期値と見る」前提から出ており、その前提自体が §1 で否定される。

### `repeat: {min: 1}` + `default:` を definition-error にする

「1 回以上必須」と「無くてもよい」が矛盾していると読む案。矛盾ではない — §4 のとおり層が違い、「1 回以上消費する、さもなくば default」は表現として意味を持つ (`--tag` を書くなら 1 つ以上、書かないなら組み込みリスト、という実用形)。DR-088 が env / config / inherit 宣言にも同じ presence を与えている以上、`min` を持つ要素だけ値源宣言を禁じる理由がない。
