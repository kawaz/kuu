# union 値淘汰の詰め所 — 枝並行構築・確定相淘汰の DR 起草前整理

> 由来: `docs/research/2026-08-13-value-capsule-design.md` (以下 **カプセルノート**) §5.6 の
> kawaz 裁定 (mid=9-10、2026-08-14) と、同 §6.2/§6.3 のレビュー 3 系統 (sol / fable / opus) の指摘。
> 本書は §5.6.5 + レビュー由来の詰め所 9 項を、確定裁定からの**導出**と**新規の発明**を峻別して
> 設計するもの。**非正本** — 規範の正本は `docs/decisions/DR-*.md`。
>
> **確定裁定 (kawaz、2026-08-14〜16。本書はこれを覆さない)**:
>
> 1. **定式**: union type の値は「枝ごとに独立並行構築 → 確定相で未完成枝を淘汰 → 生存枝の
>    最終書き込み時系列で後勝ち」(カプセルノート §5.6.1)。§5.6.2 の color 3 ケース表が正
> 2. `--r 0 --g 255 --color red --b 0` → tuple `[0,255,0]` (pos4 完成、最終書き) が `"red"` (pos3)
>    に後勝ち。`--color red --r 0` → tuple 未完成淘汰で `"red"` (`--r 0` は敗北枝の書きとして
>    消える、**エラーではない**)
> 3. これは **DR-127 §2.2/§3/§4 (時系列上書き・parse 時の枝 Reject) の supersede** である
>    (統括判定確定)。現行挙動との差分は互換考慮の対象でなく作業リスト
> 4. timerange: optional field なら `[null, until]` は完成扱いで生存 (カプセルノート §5.6.3)
>
> 各項の型は「**推し案 / 根拠 / 代替案 / 裁定要否**」。裁定要否は、確定裁定 + 既存 DR から
> 一意に導出できるものを「**導出 — 裁定不要**」、確定裁定が前提しているが表現の選択が残る
> ものを「**裁定要 (軽)**」、確定裁定から決まらない真の分岐を「**裁定要**」と区別する。

## 0. 用語の固定 (本書内)

sol M-4 の指摘 (「required 席」という語が record presence と node constraint を混同させる) を
受け、本書は以下で語を分ける:

| 語 | 意味 |
|---|---|
| **書き込み** | セルへの効果 (DR-045 の効果記述子 1 件)。丸ごと set (parser 産出含む) と path 部分書き (DR-127 §2) の両方 |
| **枝** | union value_type (DR-126 §1) の 1 variant に対応する、セル内部の候補構築状態 |
| **座の充足** | 枝の**型構造**が要求する座が埋まっていること (tuple の位置 / record の presence)。§1 で定義 |
| **node required** | 要素属性 `required` (DR-047 の遅延述語 = 値述語)。座の充足とは別位相 (§3) |
| **確定相** | 経路の消費が終わり、セル値を確定させる相 (DR-047 §4 の「値源ラダー適用後の最終状態」を作る側) |

## 1. 枝の「完成」の判定と比較キー

### 推し案

**完成 = 「枝の value_type に対する適合完成値であること」という型レベルの構造述語**とする。
node required とは無関係 (node required は §3 の位相)。

| 枝の value_type | 完成条件 |
|---|---|
| **tuple** (位置付き固定アリティ、§1b) | **全位置が non-null** — tuple は固定アリティの積型であり、位置は全て構造上必須。`[0,255,null]` は未完成 (確定裁定 2 の前提そのもの) |
| **record** (DR-126) | **closed キー適合のみ** — record のフィールドは presence-optional (DR-126 §3) なので、書き込みが 1 件以上あれば部分値 `{until: X}` でも完成。確定裁定 4 (`[null, until]` 生存) はこの帰結 |
| **primitive** (`string` / `number` / `bool`) | その型に適合する値の書き込みが 1 件以上ある |
| `array` / `map` / `value` | 型適合の丸ごと書きが 1 件以上ある (部分構築は生じない — array は vivify 不可 (DR-127 §2.2)、map / value は器の形が定義時に言えない (DR-127 §3)) |

**比較キー = 「その枝に着地した書き込みのうち、時系列で最後のものの位置」**。

- 「着地」= その枝の構造に適合して受理されたこと。丸ごと set は型適合する全枝に着地し、
  path 部分書きはそのパスを構造に含む枝だけに着地する
- 時系列 = DR-029「操作の時系列適用」の出現順そのまま。新しい座標軸は発明しない
- 帰結 (カプセルノート §5.6.5 (i) の追認): `--r 0 --b 0 --g 255 --color red` は tuple が
  pos3 で完成していても、最終着地は `--color red` (pos4) が string 枝 → `"red"` が勝つ。
  「完成した順」ではなく「最後に触った枝」が意図

### 根拠

- tuple 全位置必須は確定裁定 2 の `[0,255,null]` 未完成そのものから逆算される唯一の読み
- record 側を presence-optional のままにするのは DR-126 §3 (「closed はキー語彙の閉域であって
  全フィールドが非 null という意味ではない」「常に立つ、を機械可読に主張する手段は v1 に
  持たない」) の直接の帰結。確定裁定 4 と一致する
- 完成判定に node required を混ぜないのは DR-047 §5 (required は値述語、判定入力は最終状態) の
  位相を保つため — 淘汰は「セル値を作る」内部工程で、required は「できたセル値」への述語

### 代替案

- **record にも「必須フィールド」注釈を導入して完成判定に使う**: DR-126 §3 が v1 で明示的に
  見送った機構の再導入になり、確定裁定 4 は注釈なしで既に説明できる。v1 完備主義の観点でも
  「必要になった実例」が無い。不採用推し
- **完成 = 「required 座の全充足 + 構造検証パス」の二段**: 検証 (filter) は書き込み時点の
  位相 (§6) にあり、確定相に検証段を足すと DR-047 §2 の「事後検証層は持たない」と二重に衝突
  する。不採用推し

### 裁定要否

**導出 — 裁定不要** (record / primitive / 比較キー)。ただし **tuple の表現は §1b で裁定要 (軽)**。

### 1b. tuple 枝の表現 — 確定裁定が要求する前提の埋め方

opus C2 の指摘どおり、現行規範に tuple 型は無い: DR-126 §1 の value_type 列挙に tuple は
含まれず、DR-128 採用しなかった案 (a) が「tuple 型を value-type 体系に足す」を明示棄却済み。
また DR-127 §2.2 の array 行は vivify 不可なので、`--r 0` が空セルへ tuple 枝を部分構築する
状態は現行規範では作れない。**しかし確定裁定 2 は tuple 枝の並行構築を例の中核に置いて
承認された**ので、「tuple 相当の位置付き部分構築可能な構造」の導入は確定裁定の前提であり、
残る選択は表現だけである。

**推し案**: value_type に **tuple を第一級で追加** (`{"tuple": [<type 参照>, ...]}` —
record と同じくフィールド (位置) の型は type 参照)。vivify 可 (器は全座 null の
`[null, null, null]`)。

- **根拠**: DR-127 の根拠節「vivify を許すのは、closed record が『器の形』を定義時に確定させる
  から」の同じ論拠が tuple に成立する — 固定アリティなので器の形 (長さと各座の型) が定義時に
  尽くされる。array 行の vivify 不可の理由 (「要素の存在が実行時」) が tuple には当たらない。
  DR-128 の棄却理由「pair は定義片の `seq` がそのまま表す」は**入力側**の話であり、本件は
  **出力値の部分構築の座**という DR-128 起草時に存在しなかった要求。棄却の前提事実が変わって
  いるので、supersede は正当化できる
- **代替案**: 「固定長 array + 全座必須」の注釈で近似する。value_type の追加は避けられるが、
  (i) `[int,int,int]` の bare array 記法は union と衝突する (DR-126 §1 自身が指摘)、
  (ii) array 行の vivify 不可と矛盾する特例が生え、DR-127 §2.2 の表が「array だが例外」を
  持つことになる。型が違うものを同じ型 + 注釈で表すのは DR-102 の「違うものを違うものとして
  扱え」に反する。不採用推し
- **裁定要否**: **裁定要 (軽)** — 導出は強い (確定裁定が tuple 例を正としたことの帰結) が、
  DR-126 §1 / DR-128 の明示棄却を覆すため形式上の kawaz 承認が要る。
  合わせて DR-127 §2.2 の表に tuple 行 (静的判定 / vivify 可) を追加する

## 2. ラダーの適用単位 (sol C-2)

### 推し案

**ラダー (DR-031: CLI/link > env > config > default) はセル単位で 1 回。枝ごとに回さない。**
枝並行構築は **CLI/link の効果列 (パース時操作) の内部にだけ存在する**。

- セルへの CLI/link 書き込みが 1 件以上あれば、下位席 (env / config / default) は発火しない —
  たとえ淘汰の結果が生存ゼロでも、下位席は「救済」しない (生存ゼロは §3 のエラー)
- CLI/link 書き込みゼロなら通常のラダー: env / config の供給は string (env) または JSON 値
  (config) の**完全値 1 発**として通常の値パイプラインで parse され (DR-049 / DR-050)、
  枝並行構築は起きない — parse 産出がどの variant に適合するかという通常の型判定だけが残る。
  どの席も無ければ §5 (null)

### 根拠

- DR-031 の追記 (UX-Q7R) が明言する「ラダーの優先順位は **1 実体の値 cell 内で値源を選ぶ
  規則**」と、DR-120 §1 の「1 露出キー 1 値セル」。枝はセルの内部表現であってセルではない —
  枝にラダー席を与えると「1 セルに N 本のラダー」になり両 DR の単位を破る
- 部分書きの機構 (link パス、DR-127 §2) は CLI/link 層の住人であり、env / config / default に
  部分書きの席は無い (config_key は文法借用のみで 2 相意味論は適用外 — DR-127 波及節)。
  つまり「未完成枝」を作れるのはそもそも CLI/link だけで、下位席が「枝を完成させる」状況は
  構造的に発生しない — sol C-2 が懸念した「宣言 default が string 枝を完成させて生存する」は
  この規定の下で起こり得ない
- 「CLI 供給が壊れているとき下位席で誤魔化さない」は DR-031 の「明示的に与えられたものほど
  優先」の帰結 — CLI が最優先である以上、CLI の書き込みがある限り下位は上書きできない

### 代替案

**枝ごとに独立ラダー**: 未完成の tuple 枝を default が補完する等の表現力は増えるが、
DR-031/120 の単位を破り、sol C-2 の指摘どおり「default が生存して既存意味論が変わる」。
確定裁定はこの表現力を要求していない。不採用推し。

### 裁定要否

**導出 — 裁定不要** (DR-031 追記 + DR-120 §1 + 部分書き機構の所在から一意)。

## 3. DR-047 (required) の位相と生存ゼロエラー (fable M-1 / opus M3)

### 推し案

位相列を次で固定する:

```
消費 (書き込みの発生、書き込み単位の Reject/Error は §6)
  → 確定相: 枝淘汰 + 後勝ち → セル値が決まる (生存ゼロなら経路不成立、下記)
  → ラダー (書き込みゼロのセルのみ、§2)
  → 遅延述語 (DR-047: node required / requires / exclusive_group) を最終状態に適用
```

1. **node required は淘汰後の最終セル値に掛かる** (枝には掛からない)。DR-047 §4/§5 の
   「値源ラダー適用後の最終状態の値の有無」がそのまま適用され、改訂不要
2. **生存ゼロは「完全経路の不成立 (Error 保持)」であり、事後検証層のエラーではない**。
   DR-047 §2 の経路フィルタと同じ席に置く — 生存ゼロを含む読みは完全経路と数えず、
   他の読みが完全経路を成立させればそれが選ばれ、エラーは捨てられる (DR-037)。
   全読みで不成立なら保持された Error を表示。**これにより DR-047 §2「1 本確定後の
   事後検証層は持たない」は supersede 不要で生きる** (fable M-1 の二択の前者)
3. **エラーの kind**: 生存ゼロの Error は既存 kind に写らない (型不正でも required 欠落でも
   ない — 「供給はあったがどの枝も組み上がらなかった」)。新 reason/kind が要る。
   命名候補: `no-complete-branch` (推し — 「完成」判定 (§1) の語と接続する) /
   代替 `union-unsatisfied`。**綴りは kawaz 裁定**
4. **args_pos 帰属**: 当該セルに着地した書き込みのうち **argv 位置最深の binding の at_pos**。
   根拠は DR-053 (primary = argv 位置最深) と §1 の比較キー (最後に触った操作が意図) の同一
   原理。CLI/link 由来の書き込みが必ず 1 件以上ある (§2 — 書き込みゼロなら §5 の null で
   エラーにならない) ので `argv.length` へのフォールバックは不要だが、link 越しで at_pos を
   持たない書き込みだけの場合は消費位置 (DR-127 §4.2 の既存規則を流用)

### 根拠

- 1 は DR-047 の判定入力 (最終状態) を一切動かさない読み。DR-130 §1「null は値述語で不充足」
  もそのまま効く — 生存 1 で値が座れば required 充足、書き込みゼロで default も無ければ
  null = 不充足
- 2 は DR-047 §2 の「経路の成立条件の精密化で 1 本に絞る」メタ原理の適用。生存ゼロを即
  エラーにすると、union セルを含む読みと含まない読みが並ぶとき前者の失敗が後者の成功を
  巻き込む — DR-037「他ルートが通るならエラーは捨てる」に反する
- Error (Reject でない) 側に置くのは DR-047 §3 と同型 — 「この経路のつもりだが組み上がら
  なかった」は失敗時の表示価値が高い

### 代替案

- 生存ゼロを **Reject** (静か脱落) にする: 全滅時に「何も言わずパース失敗」になり
  DR-037/DR-127 §4.2 の帰属原則 (無言の全枝落ち禁止) に反する。不採用
- 生存ゼロを**確定相の即エラー** (経路計数に参加させない): DR-047 §2 の supersede が必要に
  なる上、得るものが無い。不採用

### 裁定要否

位相 (1・2)・帰属 (4) は**導出 — 裁定不要**。kind の綴り (3) のみ**裁定要 (軽、命名)**。

## 4. tie 規則 (sol M-5 / fable M-2 / opus M4)

複数枝が完成し、最終着地の書き込みが**同一トークン** (丸ごと set が複数枝に同時適合、
例: `{a:1}` が `{record:{a}}` と `{record:{a,b}}` の両方に適合 — DR-126 §3 presence-optional)
の場合。

### 推し案

**tie した生存枝の確定値どうしを比較し、同値なら成功 (その値)、異値なら ambiguous エラー。**

### 根拠

- **DR-031 EXP-Q1 の直接の同型**: 共露出キーの異 default は ambiguous、同値 default は
  「観測可能な競合が無いため success」。1 セルの値を複数の主体が主張するときの裁きの先例が
  既にこれで、順位規則 (宣言順) を退ける理由 (DR-038 / DR-042 の順序非依存) も同じ
- **DR-038 の経路同一性は効果列 = 観測基準**。record は構造的型付けで variant の同一性を値に
  保存しない (DR-127 §2.2 union 行) ので、確定値が同じなら観測面 (result / sources / effects)
  に差は出ない — 観測不能な tie は tie ではない
- opus M4 の別軸 tie (env 由来 vs CLI 由来で時系列比較不能) は §2 の裁定で**消滅する** —
  枝間比較は CLI/link 効果列の内部に閉じるので、時系列は常に定義される。残る tie は
  同一トークン着地だけで、本項が尽くす

### 代替案

- **無条件 ambiguous** (sol の推し): 同値 tie もエラーになる。DR-031 EXP-Q1 が「同値は
  観測可能な競合が無い」として success 側に倒した裁きと非対称になり、実害 (曖昧さの隠蔽) も
  無い場面でユーザにエラーを課す。不採用推し
- **宣言順優先**: DR-038/041 系が避けてきた経路優先規則の再導入。sol 自身が退けており同意。
  不採用

### 裁定要否

**導出寄りだが裁定要 (軽)** — EXP-Q1 からの類推は強いが、「union 枝の tie」への適用は新規の
一般化であり、sol の推し (無条件 ambiguous) と割れているため kawaz の一言が要る。

## 5. 供給ゼロ = null の適用条件 (opus M5)

### 推し案

**淘汰規則の適用条件は「そのセルへの書き込み (CLI/link 効果) が 1 件以上あること」。**
書き込みゼロのセルは淘汰規則の対象外で、通常のラダー (§2) → どの席も無ければ
DR-130 §1 の `null` (成功 result、キーは立つ)。node required があれば DR-047 で不充足
(生存ゼロエラーではなく required エラー)。

### 根拠

opus M5 の指摘どおり。「未指定の union オプションがエラーになる」は DR-130 §1 (宣言キー
全列挙 + null) と正面衝突し、確定裁定はそれを要求していない — §5.6.2 の 1 行目
(`--r 0 --g 255` → 生存ゼロ → エラー) は書き込みが**ある**ケース。ゼロ書き込みは
「全枝が未着手」であって「全枝が未完成」ではない。

### 代替案

なし (適用条件を書かない現定式は opus M5 の指摘どおり欠陥で、選択肢にならない)。

### 裁定要否

**導出 — 裁定不要**。

## 6. 書き込み自体の型不正 — 候補の Reject/Error 位相 (sol M-4)

### 推し案

**書き込み単位の失敗と枝淘汰を別位相として分離する。** sol M-4 の分類で書くと:

| 失敗 | 位相 | 扱い |
|---|---|---|
| (a) operand の型不正 (`--r abc`) | **書き込み時 (parse 時)** | 通常の値パイプライン — operand は着地フィールドの type のパーサを通る (DR-127 §3.2)。失敗は当該 filter/parser の Reject/Error (DR-037) で、**その読みの成立に効く** (枝淘汰ではない)。args_pos は原因トークン。従来規範のまま |
| (b) パスが枝の構造に無い | **書き込み時 (静的 + 適用時)** | 静的: パスを含む variant が 0 なら definition-error、含有 variant 間で型不一致も definition-error (DR-127 §2.2 union 行の静的判定 — **生存**)。適用時: パスを含まない枝には**着地しないだけ** (Reject でも Error でもない — その枝が書かれず未完成のまま残り、確定相で淘汰されうる)。ここが DR-127 §2.2 union 行の動的 Reject を置き換える中身 (§9) |
| (c) filter Reject | 書き込み時 | 従来どおり (DR-037)。読みの脱落候補 |
| (d) filter Error | 書き込み時 | 従来どおり保持 (DR-037) |
| (e) 座の充足の欠落 (tuple の null 座) | **確定相** | 枝淘汰 (§1)。エラーではない — 生存枝があれば黙って負けるだけ (確定裁定 2 の `--r 0` 消滅) |
| (f) node required | **遅延述語** | §3。枝にも書き込みにも掛からない |

### 根拠

- (a) を淘汰に吸わせると「`--r abc` が黙って消えて `--color red` が勝つ」になり、型不正の
  診断が失われる。DR-037 の Reject/Error 区別と args_pos 帰属 (原因トークン) は書き込み時に
  しか正しく取れない — DR-127 §5 が入力側バッファを退けた理由 (「Reject の発火時点が原因操作
  から遅れて args_pos 帰属が壊れる」) と同じ原理で、**位相を遅らせてよいのは「座の充足」
  (= 後続の書き込みで治りうる状態) だけ**。型不正は後続で治らないので即時に裁く
- この分離により supersede の範囲が最小になる: 動くのは (b) 適用時と (e) だけで、operand
  パース・filter の全規範 (DR-037 / DR-127 §3.2) は無傷

### 代替案

型不正も「その枝への着地失敗」として淘汰に一元化する: 診断喪失に加え、単相セルとの
非対称が生まれる (単相なら `--r abc` は型エラー、union に入れた途端沈黙する)。不採用。

### 裁定要否

**導出 — 裁定不要** (確定裁定 2 の「エラーではない」は (e) の座の欠落についての言明であり、
(a) 型不正まで含める読みは DR-037 と衝突して取れない)。

## 7. effects / sources の記録単位 (sol 指摘 8)

### 推し案

- **effects: セル単位で従来どおり、実際に発生した操作を一度だけ時系列記録** (DR-045)。
  枝への複製適用は内部表現であって効果ではない — 1 トークンが 3 枝に着地しても effects は
  1 entry。**敗北枝にしか着地しなかった書き込みも effects に残る** (`--color red --r 0` の
  `--r 0` は effects に `{entity:"color", path:[0], op:"set", operand:0, source:"link"}` として
  記録され、result には現れない)。カプセルノート §5.6.5 (ii) の「両枝の書き込みを全記録」は
  この表現に修正する (sol 指摘 8 の受理)
- **sources: 勝ち枝の値の座だけ** — sources は result の shadow (DR-122 §2「キー集合は
  result の射影」) なので、敗北枝の書き込みはタグを残さない。勝ち枝内の座タグは既存規則
  (DR-127 §6 の座単位 re-tag) のまま
- **effects の `path`**: 宣言パスの segment 列のまま (DR-127 §6)。どの枝に着地したかは
  記録しない — 枝は観測アドレスではない

### 根拠

- 「効果は観測記録であって最終状態ではない」は既存 pin が既に固定している
  (`fixtures/link-parse/value-residual-timeline.json` :: field-write-then-producer-replaces —
  消えた部分書きも effects に残る)。敗北枝の書きが effects に残るのはこの規則の適用であって
  新規則ではない。消費の or の未選択枝の書き (DR-127 §4.1b — 書きは成立、値は採用されない)
  とも同型
- 枝数分 emit しない理由は sol 指摘 8 のとおり conformance 観測の保存 (DR-045 の効果列は
  経路同一性の判定キーでもある — 枝数で effects が変わると DR-038 の経路同一性が枝表現に
  依存してしまう)

### 代替案

敗北枝のみに着地した書き込みを effects からも消す: 「実際に発生した操作」の記録という
DR-045 の性格を壊し、上記既存 pin と非対称になる。不採用。

### 裁定要否

**導出 — 裁定不要**。

## 8. 消費の or との分離 (カプセルノート §5.6.5 (iii))

### 推し案

**「トークンの食い方を分岐させるものは消費の or、食い方が同じで値の型だけが分岐するものは
セル union」**を線引きとして明文化し、両者を別機構として立てる (統括の感触 (iii) の追認):

| | 消費の or (DR-018 / DR-067 / DR-038) | セル union (本件) |
|---|---|---|
| 分岐の対象 | argv の消費構造 (何トークン食うか、どの入口か) | 1 セルの値の型 (variant) |
| 判定時点 | parse 時 — 経路探索が枝を選ぶ (完全経路 1 本、DR-038) | 確定相 — 淘汰 + 後勝ち |
| 判定材料 | 消費の成立 (読める・食える・解決できる) | 座の充足 (§1) と着地時系列 |
| 敗者の観測 | 未選択枝の named 座は result に `null` (DR-130 §2 / DR-127 §4.1b) | 敗北枝は観測に**存在しない** (セルは 1 つ、値が 1 つ。§7) |
| 曖昧の裁き | 2 本以上の完全経路 = ambiguous (DR-038) | tie (§4) |

接点は 2 つで、どちらも一方向:

1. **input_structure の or (DR-128) は消費の or 側** — type が持つ「入口の文法」の分岐は
   sub-parse のトークン消費を分けるので parse 時に選ばれる。その**産出がどの union variant に
   適合するか**が確定相の関心。同じ type の宣言に両方が同居しても位相は混ざらない
2. **枝候補状態は効果列に現れない** (§7) ので、DR-038 の経路同一性 (効果列基準) は枝表現に
   依存しない — セル union の導入は経路の数え方を変えない

また、確定裁定の枝並行構築は**出力側の候補集合**であり、DR-127 §5 が禁じた**入力側の候補
バッファ** (「入力が揃うまでパースを保留する」) ではない — 各書き込みの parse は着地時に
即時完了しており (§6 (a))、保留される入力は存在しない。§5 の禁則は無傷で生きる。

### 根拠

判定時点 (parse 時 vs 確定相)・判定材料 (消費 vs 値)・敗者の観測 (null vs 不在) の 3 点が
すべて異なる — 「違うものを違うものとして扱え」(DR-102 の kawaz 裁定) の適用。統合すると
どちらかの位相の規範 (args_pos 帰属 or 遅延淘汰) を侵す。

### 代替案

セル union を消費の or へ lowering して一元化する: 淘汰の遅延性 (確定裁定 4 の「中間 null
許容、確定相でのみ裁く」) が parse 時裁定に繰り上がって表現できず、確定裁定と矛盾する。
不採用 (確定裁定により選択肢として消えている)。

### 裁定要否

**導出 — 裁定不要**。

## 9. DR-127 の supersede 範囲 — 逐条表

確定裁定 3 (「DR-127 §2.2/§3/§4 の supersede」) の精密化。**丸ごと死ぬ節は無く、supersede は
「union 宣言セルの動的挙動」に限定される** — 単相セル (union でない record / value / array) の
全規定は無傷で、既存 fixture pin (grep 実測: union value_type の動的枝 Reject を pin した
fixture は 0 件、`fixtures/link-parse/` の現行 11 本はすべて単相セル) への影響もゼロ。

| DR-127 の節 | 判定 | 内容 |
|---|---|---|
| §1 (パス文法・表層 3 点) | **生存** | 変更なし |
| §2.1 (セル空間第 1 相) | **生存** | 変更なし |
| §2.2 遷移表 record / array / map・value / primitive 行 | **生存** | 静的判定・definition-error・vivify 可否とも変更なし (tuple 行の追加は §1b、採れば拡張であって変更ではない) |
| §2.2 遷移表 **union 行の実行時規定** (「実行時の現在値の構造で判定 — 合わなければ枝 Reject」) | **死 (supersede)** | 置換先: 書き込みはパスを構造に含む全枝へ並行着地し、含まない枝には着地しない (Reject は発生しない、§6 (b))。枝の生死は確定相の淘汰 (§1) が決める |
| §2.2 union 行の**静的規定** (パスを含む variant 0 = definition-error、含有 variant 間の型不一致 = definition-error) | **生存** | 変更なし |
| §2.3 (二相性は構造の写像) | **生存** | 変更なし |
| §3 (vivify 2 層) | **ほぼ生存** | record vivify・map/value Reject・切替深度とも変更なし。union の「含有 variant の器 `{}`」だけ読み替え: **適合する全 variant の器を並行 vivify** (1 個を選ばない)。§1b を採れば tuple の器 (全座 null) を追加 |
| §3.1 (無橋) / §3.2 (organic 値の二重保証) | **生存** | operand が着地フィールドの type のパーサを通る規定は §6 (a) の根拠としてむしろ強く依存する |

| §4.1 (退化セルの操作語彙) | **生存** | 変更なし |

| §4.2 (裁定前の枝ローカル fold・全枝落ちの ParseError 合成) | **縮小生存** | fold の要求自体は生存 (map/value の実行時解決失敗が残るため)。union variant 不適合が fold の失敗条件から抜ける。「全枝落ちの合成 ParseError」の args_pos 規則は §3-4 (生存ゼロエラーの帰属) が流用する |
| §5 (入力側への部分注入禁止) | **生存** | 枝並行構築は出力側の候補集合であり §5 の禁則の対象外 (§8 末尾)。DR 起草時にこの区別を §5 側にも注記する |

- **DR-029**「操作の時系列適用」— **生存**。時系列はセル効果列の順序として不変で、本件は
  「その適用先が union セルでは枝候補集合になる」という消費側の変化。DR-029 の counter/link

  とだけ整合を確認)
- **DR-126** — §1 (union は 2 要素以上の value_type) / §3 (presence-optional) / §4 (乖離

- **DR-128** — input_structure の or は消費側 (§8) で無傷。§1b を採る場合「採用しなかった案
  (a)」に supersede 注記
- **DR-047 / DR-031 / DR-120 / DR-130 / DR-045 / DR-037 / DR-038** — §2〜§8 のとおり
  すべて supersede 不要 (生存ゼロを経路フィルタに置く §3 の設計がこれを成立させている)

### 裁定要否

**導出 — 裁定不要** (確定裁定 3 の範囲を既存規範の依存関係で機械的に切り分けたもの。
ただし §1b の tuple 裁定の結果で 2 行 (tuple 行追加・DR-128 注記) が増減する)。
